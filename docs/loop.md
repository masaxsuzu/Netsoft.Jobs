# ループの実測

`/retro` が 10 PR ごとに置き換える。**git の履歴がそのまま推移になる**ので、
前回との差は `git log -p docs/loop.md` で読む。

数え方は [tools/loop-stats/loop-stats.py](../tools/loop-stats/loop-stats.py)、
手順は [.claude/skills/retro/SKILL.md](../.claude/skills/retro/SKILL.md)。

## 2026-08-06  #1〜#71

| 指標 | 全体 | 直近 20 件 |
|---|---|---|
| PR | 71 件 | 20 件 |
| マージ済み | 71 / 71 (100%) | 20 / 20 (100%) |
| マージまでの中央値 | 3 分 | 2 分 |
| マージまでの最大 | 10.1 時間 | 10.1 時間 |
| needs-review | 33 / 71 (46%) | 6 / 20 (30%) |
| 　… その中央値 | 8 分 | 10 分 |
| 　… 以外の中央値 | 2 分 | 2 分 |
| テンプレート充足 | 66 / 71 (93%) | 20 / 20 (100%) |
| 実測の記載 | 56 / 71 (79%) | 16 / 20 (80%) |

### 読み取り

- **`needs-review` は効いている。** 付いた PR はマージまで中央値 8 分、付いていないものは 2 分。
  直近 20 件だと 10 分と 2 分で、**#68 で基準を絞ってから差が開いている**（46% → 30%）
- **効き方は「レビューを呼ぶ」ではなく「auto-merge を保留して手を止める」。**
  GitHub 上のレビューは #1〜#71 で 0 件だが、それはラベルの失敗ではない。
  レビューを呼ぶ仕組みはどこにも無く、**あるのは auto-merge を有効にしないという一手だけ**
- **マージまでの中央値が 3 分。** CI が通れば即マージされている。ここは詰まっていない
- **テンプレート充足が直近 100%。** #71 で push を機械で止めたので、次の回も落ちないことを見る
- **実測の記載が 79% で動いていない。** 「確認したこと」に数字を書かない PR が 2 割ある。
  規則としては `/ship` に書いてあるので、効いていない側の候補

### この回で直したこと

初回は「`needs-review` の的中（GitHub 上のレビュー）」を測り、0/33 だった。
**指標の方が間違っていた。** ラベルに GitHub のレビューを呼ぶ働きは無く、
0% は「効いていない」ではなく「そこを見ていない」を意味していた。
止まったかどうかはマージまでの時間に出るので、そちらに置き換えた。

**指標が 0 のまま動かないときは、規則より先に指標を疑うこと。**
