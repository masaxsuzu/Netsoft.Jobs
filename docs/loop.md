### 読み取り

- **`needs-review` は 3 回続けて下がっている。** #1〜#67 で **46%（31/67）**、
  #68 以降で **29%（7/24）**、直近 20 件で **25%（5/20）**。
  #68 で 3 つの条件に絞ってから、絞り続けている。
  **効き方も開いた** ── 付いた PR は中央値 14 分、付いていないものは 2 分（前回は 12 分と 2 分）。
  基準は触らない
- **テンプレート充足は直近 100% を 3 回連続で維持。** #71 で push を機械で止めた効果が続いている
- **実測の記載は直近 90% → 95%。** 欠けているのは #81 の 1 件だけで、スキルの判定済みリストに
  行を足しただけの PR ── 書く数字が無い。実質 19/19
- **マージまでの中央値（直近 20 件）が 6 分 → 7 分。悪化ではない。**
  伸ばしているのは #78 (333 分・GitHub Actions の障害)、**#89 (130 分)**、#85 (85 分)、
  #77 (84 分)、#76 (72 分)、**#88 (60 分)**。前回の窓から新しく入ったのは #89 と #88 だけ

#### #89 と #90 の差が、この回でいちばん読めるもの

| | #89 | #90 |
|---|---|---|
| 中身 | 一覧の見た目（列幅・絵柄・文言） | 監査ログ（Domain から Ui まで、3 コミット） |
| マージまで | **130 分** | **2 分** |

**差を作っているのは変更の大きさではない。**#90 のほうが桁違いに大きいのに 2 分で終わっている。
#89 で直したのは、進捗の数字・失敗理由の出し方（2 回）・ボタンの絵柄・状態の文言・
待ち行列の順序 ── **どれも「画面に何が出るか」で、CLAUDE.md が「聞く」と決めている側**。

規則（*答えが画面や API の見え方を変えるなら聞く*）は正しく、**#89 は当てはめ損ねた**。
#67 で「4 往復は多すぎる」と書いたのと矛盾しない ── あちらで多すぎたのは実装の選び方の質問で、
こちらで足りなかったのは見え方の質問。線はもう引かれていて、守れていなかっただけ。

**n=2 なので規則は変えない。**次の回で、見え方を変える PR がまた長くなるかを見る。

### この回で試して、入れなかったもの

**PR の大きさとマージまでの時間の相関を測ろうとして、データが取れなかった。**
「時間を決めているのは大きさか、往復か」を切り分けたかった。

`list_pull_requests` の応答に `additions` / `deletions` / `changed_files` / `commits` が
入っておらず（`fields` で指定しても返らない）、四分位に分けたら全部 0 行になった。
**91 件を個別に取れば埋まるが、ダンプの取り方が 1 リクエストから 91 リクエストへ変わる。**

指標の筋が悪かったのではなく、取れるデータの形の問題。必要になったら
`.claude/skills/retro/SKILL.md` のダンプ手順ごと変える判断が要る。

### この回で直した規則

**#91 でゲートの待ち方を 3 つ足した。**このセッションで「テスト待ちで止まっていないか」と
問われて測ったもので、**止めていたのはゲートそのものではなく待ち方の事故だった**。

ゲートは 1 回 **77 秒**（build 5 秒 / テスト + カバレッジ 30 秒 / format 27 秒）。
テストの 30 秒を作っているのは件数ではなくプロセス起動の数で、Domain の 195 件が 0.6 秒に対し
E2E 9 秒とストレス 15 秒。**削れば消えるのは一番守りたい部分**なので、縮める余地は無い。

| 足した規則 | 実際に起きた回数 |
|---|---|
| ゲートの手前で全テストを回さない（結果は使われず捨てている） | 4 回 |
| 背景タスク 1 本で待ち、`Monitor` を重ねない | 3 回 |
| `pkill` は `\|\| true` で締める | 5 回以上 |

置き場は `.claude/skills/ship/SKILL.md`。ここ（loop.md）ではなくあちらにしたのは、
loop.md が 10 PR ごとに**置き換わる**場所で、手順そのものは置き換えの対象ではないため。

**それ以外は無し。** 効いていない規則が見つからなかった。`needs-review`・テンプレート充足・
実測の記載はどれも動いており、数字を良く見せるためだけの変更はしない
（docs/build.md のカバレッジと同じ考え方）。
